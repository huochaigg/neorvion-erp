# V2.3.3 动态权限菜单、页面访问控制与按钮权限

## 1. 业务目标

在现有 RBAC 上，让 ERP 菜单、页面和按钮跟随当前租户成员的有效权限变化。

不重新设计 RBAC、TenantContext、JWT 或 Wujie 生命周期。不开发商品、订单、库存实际业务。不实现 WebSocket 权限推送。

## 2. 权限获取流程

1. 浏览器带 Access Token 与 `X-Tenant-ID` 请求 `GET /api/v1/tenants/current/my-permissions`。
2. FastAPI 先走 `TenantContextDep`（登录、成员有效、租户有效）。
3. `AuthorizationService.current_member_access` 按当前 `tenant_id + member_id` 读取角色，并把多角色权限取并集。
4. OWNER 仍按现有所有权规则拥有目录全部权限。
5. 前端用 React Query 缓存，Query Key 为 `['tenant', tenantId, 'my-permissions']`。

同一用户在不同企业必须分别查询。不能把租户 A 的权限渲染到租户 B。

## 3. routes.ts 权限配置

`apps/erp/src/router/routes.ts` 仍是 ERP 路由与菜单的唯一来源。

字段：`permission`、`permissions`、`permissionMode`（`any` | `all`）。

- 工作台未声明权限：当前有效成员可访问。
- 商品 / 库存 / 仓库 / 订单占位页声明对应 `*:read`（创建、编辑页声明 `create` / `update`）。
- 成员管理：`tenant:member:read`；角色管理：`tenant:role:read`。
- `showInMenu: false` 仍走页面守卫，不因隐藏菜单而放行。

菜单由 `filterMenuRoutes` 递归生成。有可见子项的分组保留；没有任何可见子菜单的空分组隐藏。React Router 仍保留全部受保护路由，避免无权限访问变成含糊的 404。

## 4. 页面权限守卫

`PermissionGuard` 包在 `Outlet` 外：

- 权限加载中：Spin，不渲染受保护页面。
- 有权限：正常渲染。
- 无权限：403 页面。不登出、不 Refresh。
- 无租户 / 未登录仍由现有工作空间与认证流程处理。

## 5. 按钮权限组件

```tsx
<Can permission="tenant:member:manage">
  <Button>添加成员</Button>
</Can>
```

支持 `permissions` + `mode`。默认无权限时隐藏。系统角色与 OWNER 的业务保护仍以后端为准。

## 6. 租户切换权限隔离

沿用 V2.2.4 的 `tenant-store`、`TenantChangeBridge`、`isolateTenantQueries`、epoch 重挂载。

切换后新 `tenantId` 的 Query 进入 loading，不会用 A 企业权限画 B 企业菜单。不重新 RSA 登录，不无意义 Refresh，不 `destroyApp`。

角色权限修改成功后失效 `my-permissions` 与角色/成员缓存。其他在线用户本版不推送，下一次请求或窗口聚焦时以后端当前权限为准。

## 7. 后端接口校验

成员与角色接口继续使用 `require_permission()`。直接调用 API 无法绕过前端隐藏。

新增：`GET /api/v1/tenants/current/my-permissions`，返回 `{ roles, permissions }`。  
`GET /api/v1/tenants/current` 仍返回 `permission_codes`，两套数据都来自 `AuthorizationService`。

无新表、无新迁移。

## 8. 测试结果

- 后端：`uv run ruff check app tests` 通过；`uv run pytest` **85 passed**（含 `test_my_permissions.py` 5 个用例：当前权限、多角色并集、租户隔离、无权限 403、撤销后立即生效）。
- 前端：`pnpm --filter @neorvion/shell test` **14 passed**；`pnpm --filter @neorvion/erp test` **25 passed**（菜单递归、空父级、403、加载中不放行、按钮权限、租户隔离、Query Key）。
- 构建：`pnpm --filter @neorvion/erp build` 与 `pnpm --filter @neorvion/shell build` 通过。
- 浏览器：Wujie 子应用在 iframe 内，当前浏览器工具无法点选 ERP 菜单做完整点击验收；页面契约由 Vitest + TypeScript 构建覆盖。

## 9. 遗留问题

- 无 WebSocket 实时踢人；其他会话下次请求才看到权限变化。
- 全站 Shell 侧栏裁剪不在本版。
- OWNER 转移仍未实现。
- 商品、订单、库存仍是占位页，只按权限显示入口。
