# V2.3.5 — RBAC 管理体验完善与菜单按钮权限树

本版收尾 V2 的 RBAC 与系统管理。不引入第二套权限模型，不开放租户自建菜单或权限编码。下一版本进入 V3 商品 / SPU / SKU。

## User 与 TenantMember 的 display_name

- **User.display_name**：平台级登录账号名称，企业管理员不能通过成员接口修改。
- **TenantMember.display_name**：该用户在某一企业内的展示名，可为空。

展示规则：`tenant_member.display_name ?? user.display_name`。

同一人可在 A 企业叫「张三」、B 企业叫「张经理」。改 B 不影响 A，也不改全局账号。历史数据不强制回填，字段可空。

## 为什么 Permission 不开放租户 CRUD

`PermissionCode` 表示代码里真实存在的能力（`require_permission`）。如果租户自己建 `inventory:super-delete`，而路由和 Service 从未校验它，该行没有意义。

因此：

- **系统有哪些权限**：开发人员定义，seed 幂等写入 `permissions`
- **角色拥有哪些权限**：租户管理员配置 `role_permissions`
- 权限目录页只读。旧的 `tenant:member:manage` / `tenant:role:manage` 标记废弃，不物理删除

## 菜单 / 页面 / 按钮权限树

没有新增 `system_resources` 或 `role_menus`。资源树写在 `PERMISSION_TREE`（程序定义），`GET /api/v1/permissions/tree` 补上 `permission_id`。

- DIRECTORY：分组，没有 Permission
- MENU：页面对应路由，通常由子 ACTION 的 read 控制菜单显示
- ACTION：按钮/接口，对应 `PermissionCode`

勾选树后只提交 `permission_ids`。父节点全选只是批量勾子节点。`routes.ts` 仍是真实 React 路由来源：数据库不能随便长出前端页面。

## 细粒度系统管理权限

成员：`read` / `create` / `update` / `role:update` / `disable` / `remove`  
角色：`read` / `create` / `update` / `delete` / `permission:update`  
目录：`tenant:permission:read`

拥有旧 `*:manage` 的角色在迁移 `20260928_0006` 中展开为对应细粒度权限。运行时 `AuthorizationService` 仍把旧 manage 视作拥有细粒度，避免升级窗口 403。

## 角色规则

- 系统角色（OWNER / ADMIN / OPERATOR / WAREHOUSE / VIEWER）：后端按 `is_system` 禁止删除
- OWNER：禁止通过管理接口改核心权限
- ADMIN：可调业务权限，必须保留租户管理细粒度编码
- 自定义角色：可改 name/description；code 创建后只读；未使用可删
- 仍被 `member_roles` 引用：`40041` + `ROLE_IN_USE` + `member_count`，不级联解绑
