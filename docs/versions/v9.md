# V9 — 物流与发货

销售履约从仓库出库继续走到承运商发货、轨迹和签收。库存只在 V8 确认出库时扣一次。

## 范围

- 物流商档案
- 物流单 / 物流明细 / 手工轨迹
- 确认发货、部分发货、签收、订单完成
- 销售订单状态把仓库出库和物流发货分开
- 销售明细区分 `outbound_quantity` 与 `shipped_quantity`
- 多租户、RBAC、React 页面、测试、文档

## 不包含

真实 DHL / UPS / FedEx / 顺丰 API、电子面单、自动轨迹、平台发货回传、运费、退货、退款、售后、财务、调拨、盘点、AI Agent。不要自动开始 V10。

## 状态迁移

V8 用 `PARTIALLY_SHIPPED` / `SHIPPED` 表示仓库已出库，会和物流发货混淆。

Alembic `20261008_0015`：

- 新增 `outbound_quantity`，把当时的 `shipped_quantity` 拷过去，再把 `shipped_quantity` 置 0
- `PARTIALLY_SHIPPED` → `PARTIALLY_OUTBOUND`
- `SHIPPED` → `OUTBOUNDED`

开发数据没有真实物流发货，这个迁移是安全的。

## 销售订单状态

```text
DRAFT → PENDING_CONFIRMATION → WAITING_OUTBOUND
  → PARTIALLY_OUTBOUND → OUTBOUNDED
  → PARTIALLY_SHIPPED → SHIPPED → COMPLETED
```

旁路：草稿 / 待确认 / 待出库可取消。已经正式出库后不能整单取消。

## 主要接口

- `GET/POST /api/v1/carriers`
- `GET/PATCH /api/v1/carriers/{id}`
- `PATCH /api/v1/carriers/{id}/status`
- `DELETE /api/v1/carriers/{id}`
- `GET/POST /api/v1/shipments`
- `GET/PATCH /api/v1/shipments/{id}`
- `POST /api/v1/shipments/{id}/confirm|cancel|deliver`
- `GET/POST /api/v1/shipments/{id}/tracking-events`

创建入口只有 `POST /shipments`。出库详情页跳到创建页，不另做一套创建逻辑。

## 权限

`carrier:read/create/update/disable/delete`

`shipment:read/create/update/confirm/tracking:update/deliver/cancel`

OWNER / ADMIN 全部。OPERATOR 可读物流商，可创建、编辑、确认、轨迹、签收、取消物流单。WAREHOUSE 可读物流商，可创建和确认发货。VIEWER 只读。

## 前端

菜单「物流管理」：物流单、物流商。出库详情可创建物流单。销售订单详情展示出库 / 发货数量和物流单列表。
