# V3 — 商品管理（SPU / SKU / 类目 / 品牌）

本版进入 ERP 核心业务。完成商品档案闭环：类目 → 品牌 → SPU → 规格 → SKU → 列表/详情 → 新增编辑启停 → RBAC → 多租户隔离。

不开发仓库、库存、采购、销售订单、出入库、物流。

详见 `docs/products.md`。

## 数据表

迁移 `20260928_0007`：

- `product_categories`：租户类目树，`parent_id` 自关联，最多三级；第三级不可再挂子节点
- `brands`：租户品牌，`(tenant_id, code)` 唯一
- `products`：SPU，`(tenant_id, code)` 唯一；新增可不填 `code`，flush 后按 id 生成 `PD` + 10 位数字
- `product_skus`：SKU，`(tenant_id, sku_code)` 唯一，`spec_values` 为 JSON；新增可不填 `sku_code` / `barcode`，分别生成 `SKU` + 10 位数字、缺省等于 `sku_code`

复合外键保证类目 / 品牌 / 商品 / SKU 同租户。

## API

均需登录和 `X-Tenant-ID`。

- `GET/POST /api/v1/product-categories`
- `PATCH/DELETE /api/v1/product-categories/{id}`
- `GET/POST /api/v1/brands`，`GET /api/v1/brands/options`
- `PATCH/DELETE /api/v1/brands/{id}`
- `GET/POST /api/v1/products`，`GET/PATCH /api/v1/products/{id}`
- `POST /api/v1/products/{id}/skus`
- `PATCH/DELETE /api/v1/products/{id}/skus/{sku_id}`

创建商品时 Product + SKUs 同一事务。未填写的商品/SKU 编码用自增 id 生成，不用 `MAX(code)+1`。SKU 数量列表用 SQL 聚合，不用把全部 SKU 拉进内存 `len()`。

## 前端

菜单「商品管理」：

- `/products/list` 商品列表
- `/product-categories` 类目管理
- `/brands` 品牌管理

隐藏页：`/products/create`、`/products/:id`、`/products/:id/edit`。路由仍只写在 `apps/erp/src/router/routes.ts`。

Query Key 带 `tenantId`，例如 `['tenant', tenantId, 'products', filters]`。

## 权限

继续使用 `product:read/create/update/delete`。类目和品牌不另拆编码。权限树增加「类目管理」「品牌管理」菜单节点，叶子仍映射上述 code。

OPERATOR 默认不能 `product:delete`。WAREHOUSE / VIEWER 只读。
