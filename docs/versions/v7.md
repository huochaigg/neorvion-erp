# V7 — 销售订单管理

本版完成客户档案、销售订单、订单明细、状态机、确认时库存预占、取消时释放预占、RBAC、React 页面与联调。

确认后进入待出库，只增加预占，不减少实际库存。拣货、出库、发货、物流、平台同步、退货退款不在本版。

下一完整版本建议 V8 出入库与履约：采购收货入库，以及销售订单拣货出库。不要在本版继续往下做。

详见 `docs/orders.md`。当前有效架构见 `docs/current-state.md`。

## 数据表

迁移 `20261005_0012`：

- `customers`：`UNIQUE(tenant_id, code)`。未填 code 时 flush 后写 `CUS` + 10 位 id。
- `sales_orders`：`UNIQUE(tenant_id, order_no)`，以及 `UNIQUE(tenant_id, source, external_order_no)`。单号 `SO` + 年 + 6 位 id。客户 / 仓库复合外键。收货地址是下单快照。
- `sales_order_items`：`UNIQUE(tenant_id, sales_order_id, sku_id)`。`quantity > 0`，`reserved_quantity` / `shipped_quantity` 默认 0，且 `shipped <= reserved <= quantity`。

## 状态机

`DRAFT` → `PENDING_CONFIRMATION` → `WAITING_OUTBOUND`。三种未结束状态都可以 `CANCELLED`。

草稿和待确认不碰库存。确认调用 `InventoryService.reserve_within_transaction`，取消待出库调用 `release_within_transaction`。订单 Service 持有同一个 Session，库存方法不自己 commit。

同一订单的确认、取消、提交、草稿编辑用 `SELECT FOR UPDATE` 串行。库存仍用 V5 条件 UPDATE。多 SKU 按 `sku_id` 升序加锁，避免死锁。

## API

- 客户：`/api/v1/customers` CRUD + `/status`
- 订单：`/api/v1/sales-orders` 列表 / 创建 / 详情 / 编辑
- 动作：`/submit` `/confirm` `/cancel`
- 提示：`GET /api/v1/inventory/availability`

## 前端

菜单「订单管理」：销售订单、客户管理。创建 / 详情 / 编辑不进菜单。详情用 Timeline。库存不足展示 SKU、可用量和需求量。

## 权限

补齐 `order:update` / `order:submit`，以及完整 `customer:*`。确认沿用 `order:audit`。OPERATOR 不能确认订单，客户默认只读。
