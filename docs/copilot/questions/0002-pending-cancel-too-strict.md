# 0002 Pending 取消口令过严，纠正/重开被当成补参

- 状态：待修复
- 日期：2026-11-25
- 范围：`SkillInputCollector.cancelled` + `PendingSkillService.resume`
- 关联：[0001](0001-sku-query-stuck-on-sales-order-review.md)

## 复现

已卡在 `sales-order-review` 补 `order_id` 时发送：

- `重新开始：帮我看下某个sku的销售情况，不是销售订单，而是sku！！！`
- `你应该让我补充sku，而不是订单`
- `傻不愣登的`

全部仍回复「请补充以下必填参数：销售订单主键…」。

## 期望

「重新开始」「不是销售订单，而是 sku」应结束或切换 Pending，而不是继续收集订单主键。抱怨/纠正类短句也不应继续套旧 schema。

## 实际

取消只认**整句恰好**是以下之一（可带句号/感叹号/空白）：

```text
取消 | 算了 | 停止 | 不用了 | cancel
```

对应：

```python
r"^(?:取消|算了|停止|不用了|cancel)[！!。.\s]*$"
```

「重新开始：…」不是 fullmatch，`resume()` 把它当补参文本。补不出 `order_id` 就原提示再出一遍。Skill 选择器根本不会跑。

## 临时绕过

单独发 `取消`，等「已取消本次 Skill 参数收集」后再问新问题。

## 后续可改方向（未实施）

- 识别「重新开始 / 换一个 / 我不是问订单」并取消 Pending
- 补参失败且新消息与当前必填字段类型冲突时自动取消并重新选择
- 前端在 Pending 期间展示「正在收集 xxx，发送取消可中止」避免用户以为已经重开
